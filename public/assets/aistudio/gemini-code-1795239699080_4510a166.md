# Screen Earner — Phased Enhancement & Transaction Traceability Prompt

## Role & Objective
You are an Android/Kotlin automation engineer enhancing **Screen Earner** (`predict-manager` / `ScreenEarner`). Implement the **30 improvement priorities** below in **separate, controlled phases** following the **Priority Roadmap**, treating every bet as a **traceable transaction** and preserving the currently working betting engine rather than changing everything at once.

These items are **additional improvement priorities**, not claims that every item is currently broken. Keep existing working automation, OCR/Accessibility fusion, unified floating hand, settings panels, and progression controls intact, and do not introduce breaking changes across unrelated modules.

---

## Core Architectural Principle: Traceable Transactions
Make every bet a **traceable transaction** across its full lifecycle so the app knows:
- **Which round** triggered it (unique round ID),
- **What stake was intended**,
- **What stake the game accepted**,
- **Whether Cash Out actually succeeded**, and
- **What result was finally recorded** (distinguishing true wins/losses from failed clicks, rejected bets, unconfirmed actions, or uncertain outcomes).

This ensures higher automation reliability and trustworthy strategy analysis.

## Improvement Priorities (Items 1–30)

### 1. Automation Intelligence and Reliability
1. **Complete round-state management:** Use one authoritative state machine for `WAITING`, `BETTING`, `ACTIVE FLIGHT`, `CASH-OUT`, `CRASHED`, `SETTLED`, and `RECOVERY`. Prevent actions from carrying over into another round.
2. **Round identification:** Give every detected round a unique identifier. Link its pattern, stake, `BET` action, multiplier, `CASH OUT` action, and final result to that same round.
3. **Action synchronization:** Prevent OCR, Accessibility, monitoring, and automation callbacks from executing conflicting actions simultaneously.
4. **Automatic recovery:** Recover from temporary Accessibility disconnection, OCR failure, overlay interruption, screen rotation, and game reload without duplicating bets.
5. **Game-specific adapters:** Support different crash games through separate detection and interaction configurations rather than assuming every game has identical controls.

### 2. Better Strategy and Pattern Intelligence
6. **Strategy performance comparison:** Compare strategies by actual recorded profit/loss, win rate, number of attempts, drawdown, and failed executions.
7. **Pattern reliability scoring:** Show how frequently a pattern occurs, how many times it was tested, and its historical outcomes.
8. **False-signal tracking:** Record patterns that triggered a bet but produced unsuccessful results. Use these records to improve strategy evaluation.
9. **Strategy isolation:** Each strategy should have its own configuration, performance records, activation state, and progression rules.
10. **Backtesting:** Test strategies against historical recorded rounds without placing real bets. Clearly distinguish simulated results from actual results.

### 3. Financial and Loss Protection
11. **Maximum stake protection:** Never exceed a user-configured maximum stake, even when progression is enabled.
12. **Session exposure:** Display the total amount currently at risk, not just the latest stake.
13. **Daily and session limits:** Add maximum loss, maximum consecutive losses, maximum bets, and optional profit targets.
14. **Balance verification:** Detect when the displayed balance changes unexpectedly and suspend automation until reconciled.
15. **Failed-action accounting:** Distinguish a lost bet from a failed click, rejected bet, unconfirmed bet, or uncertain result. Never treat them as equivalent.

### 4. OCR and Game Understanding
16. **Detection confidence dashboard:** Display OCR confidence, Accessibility confidence, last successful screen scan, and current game-state confidence.
17. **Stale-data protection:** Automatically invalidate old multiplier, stake, button, and countdown readings.
18. **Game interface changes:** Detect when a game changes layout, moves buttons, or updates its interface. Require recalibration instead of blindly using old positions.
19. **Numeric validation:** Distinguish stake values, balances, multipliers, and historical results so OCR does not confuse numbers from different screen areas.
20. **Capture performance:** Control OCR frequency, image processing, and battery usage without sacrificing critical betting-window detection.

### 5. Floating Hand and User Experience
21. **Clear action status:** Show `READY`, `VERIFYING`, `BETTING`, `BET CONFIRMED`, `IN FLIGHT`, `CASHING OUT`, `COMPLETED`, or `BLOCKED`.
22. **Manual override:** Allow the user to stop an upcoming action immediately without deleting recorded information.
23. **Action feedback:** Show exactly what happened after every hand tap, including failed or rejected actions.
24. **Position safety:** Prevent the hand from covering the game's important controls and remember its position per game.
25. **Connection indicator:** Show whether monitoring, OCR, Accessibility, and automation are independently connected.

### 6. Data, Diagnostics and Maintenance
26. **Complete action history:** Record timestamps, round IDs, intended actions, detected targets, actual clicks, verification results, and failure reasons.
27. **Diagnostic screen:** Provide a clear explanation when automation is unavailable instead of simply displaying `OFF` or `ERROR`.
28. **Database integrity:** Protect historical records against duplicate rounds, duplicate settlements, and interrupted writes.
29. **Service health monitoring:** Detect crashed, stopped, or disconnected background services and report which component needs attention.
30. **Exportable reports:** Allow users to export recorded rounds, strategy statistics, and execution logs for external analysis.
