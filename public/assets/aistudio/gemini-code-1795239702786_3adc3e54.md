## 1. Additional Critical Logic Defects (High Priority)

### 1.1 Automation Can Unlock While an Earlier Action Is Still Running
- **File:** `data/engine/AutomationEngine.kt`
- **Defect:** Forcibly resets `isActionInProgress` after 7 seconds (`(System.currentTimeMillis() - actionStartedAtMs.get()) > 7_000L` -> `isActionInProgress.set(false)`). A timeout does not prove a slow stake edit or gesture stopped, risking overlapping actions.
- **Required Fix:** Use an **action ownership token** and **cancellable job**. Never unlock an action simply because a timeout elapsed.

### 1.2 Crash Recording Has a Concurrency Race
- **File:** `data/engine/LiveCrashPipeline.kt`
- **Defect:** `flushPendingNow()` and the debounce collector can both call `confirmAndEmitCandidate()`. Deduplication check and insertion into `recordedDedupKeysInSession` are not protected by a mutex or atomic transaction, creating a duplicate-emission race during rapid round transitions.
- **Required Fix:** Serialize candidate confirmation, make deduplication **atomic**, and enforce **database uniqueness** as the final protection.

### 1.3 OCR Can Publish an Old Result After Capture Stops
- **File:** `service/ScreenOcrAnalyzer.kt`
- **Defect:** `release()` closes the recognizer, clears the latest snapshot, and resets `isBusy`, but an in-flight ML Kit callback can still complete afterward and publish an old snapshot, and resetting `isBusy` can let another OCR task start while a prior task is still finishing.
- **Required Fix:** Introduce a **capture-generation ID**. Every OCR callback must verify that it matches the **currently active capture generation** before publishing results.

### 1.4 Daily Loss Protection Can Fail Open
- **Files:** `service/AutomationController.kt`, `service/SessionStateManager.kt`, `data/engine/AutomationEngine.kt` (and `RiskManager.kt`)
- **Defect:** `sessionStateManager?.getDailyLoss(nowMs) ?: 0.0` treats an unavailable session manager/loss record as `0.0` (no daily loss), making an unreadable loss state appear safe.
- **Required Fix:** When daily loss protection is enabled, **unavailable or unreadable daily-loss data must fail closed** and **block new bets until reconciled**.

## 2. Other Important Execution Problems (Needs Improvement)

### 2.1 Cash Out Recognition Can Mistake a Disappearing Button for Success
- **File:** `data/engine/AutomationEngine.kt`
- **Defect:** During flight, transitioning from `CASH OUT AVAILABLE` to `IDLE_READY_TO_BET` or `BET_QUEUED` can be treated as cashed out even if the game crashed, changed screens, or rejected the Cash Out.
- **Required Fix:** Explicitly distinguish:
  1. `Cash Out requested`
  2. `Gesture dispatched`
  3. `Game accepted Cash Out`
  4. `Payout confirmed`
  5. `Round crashed without confirmed Cash Out`
  Only a **confirmed payout** counts as a win.

### 2.2 Generic Text-Click Automation Has a Dangerous Fallback
- **Files:** `service/ScreenEarnerActionExecutor.kt`, `ScreenEarnerMacroRunner.kt`
- **Defect:** `clickText()` tries clicking a matching node, and on failure taps the center of the matched text node's bounds—which may be a non-clickable label rather than the control itself.
- **Required Fix:** Never fall back to tapping arbitrary text bounds for financial actions. Require a **verified clickable target** and **reject ambiguous matches**.

### 2.3 Screen Rotation Can Invalidate Coordinates
- **File:** `service/ScreenCaptureProjectionService.kt`
- **Defect:** Capture dimensions are read from display metrics when projection starts without a full recalibration workflow for display rotation or resolution changes, desynchronizing OCR bounds and Accessibility bounds.
- **Required Fix:** Detect display configuration/rotation/resolution changes (and game layout changes), **invalidate old coordinates**, and **wait for a fresh screen capture and target scan** before allowing actions.

### 2.4 Session Cleanup Uses Blocking Coroutine Calls
- **File:** `service/AutomationController.kt`
- **Defect:** `runBlocking` calls in session cleanup and background-loop cancellation can freeze the UI if called on the main thread while waiting on jobs or database work.
- **Required Fix:** Use **suspend functions** and **lifecycle-managed coroutines** for cleanup so stopping automation never blocks the main thread.

## 4. Missing Protection: Interrupted Transaction Recovery & Authoritative Transaction Manager

### 4.1 Single Authoritative Transaction Manager
- Add a **single authoritative transaction manager** shared across `AutomationEngine`, Accessibility service, OCR (`ScreenOcrAnalyzer` / `ScreenCaptureProjectionService`), and the recording pipeline (`LiveCrashPipeline`).
- Every component reports **evidence** to it, while **only the transaction manager authorizes state transitions and settlement**.

### 4.2 Persistent Transaction Journal & Bet Lifecycle
Implement a persistent transaction journal recording every transition with:
- `gameId`
- `roundId`
- `actionId`
- `timestamp`
- `evidence`

Required bet transaction lifecycle states:
1. `INTENT_RECORDED`
2. `STAKE_VERIFIED`
3. `AUTO_CASHOUT_VERIFIED`
4. `BET_DISPATCHED`
5. `BET_ACCEPTED` / `BET_UNCONFIRMED`
6. `CASHOUT_DISPATCHED`
7. `CASHOUT_CONFIRMED` / `ROUND_LOST` / `OUTCOME_UNKNOWN`
8. `SETTLEMENT_RECORDED`

### 4.3 Restart & Interruption Reconciliation
- Handle scenarios where Android kills the automation service after stake editing or `BET` dispatch before success is recorded.
- On restart, reconcile unfinished transactions against the actual game state and **never automatically repeat an uncertain `BET`**.
